## 1. The workflow, as stated by the user on 21 September

Written here first because every finding below is measured against it.

**Shooters**

1. Shoot. Some camera systems record RAW, some do not.
2. **Where RAW is recorded, debayer to a basic file type**, only when necessary, **baking in
   nothing and choosing no colours**. The encoding therefore stays camera-native log.
3. Bring the clips into Resolve.
4. Set each clip to **24.000 even**.
5. Build a **stringout**.
6. **Add the metadata to the clips**: the shot code in `Shot`, the element code in `Shot Type`,
   the encoding in `Gamma Notes` and `Color Space Notes`.
7. **Copy with trim, consolidating, not transcoding.** One file per timeline clip, camera
   filenames kept, camera timecode kept, handles, and Resolve writes a `.drt` beside the media
   as a by-product.
8. The consolidated timelines go to Ben.

**Ben**

9. Final trims and the grade, in Resolve.
10. **Exports a CSV and an EDL with the CDL in it.**

**The tool**

11. Folders, filenames, every export format, and the colour.

### The one place the evidence disagrees with the description

The user's words were that the metadata "travels with the consolidated clips or in the csv file".
In `Turnover199` it travelled **only** in the CSV. Verified three ways on 21 September: all 81
hex blobs in the `.drt` decoded and searched (no `Shot`, no `TEST0001`, no `Gamma Notes`), and the
consolidated MP4s carry no user data but Resolve's 72-byte encoder tag.

Resolve can import media pool metadata from a CSV, so the chain works. But it means **the
shooters' CSV is a required handover item to Ben**, and no document says so. If a shooter omits
it, Ben's export carries blank identity columns and the tool cannot name a single deliverable.
That is a single point of failure with no check in front of it.

### A2. The delivered format is not ProRes 4444, in 7 places

`PRD.md:44`, `docs/COLOR_AND_FORMAT.md:184`, `:363`, `:555`, `docs/QC_RULES.md:43` (QC-021),
`docs/ARCHITECTURE.md:77`, `docs/WORKFLOW.md`.

What is true: consolidated **camera-native** media, copied with trim and **not transcoded**, or
for a RAW system a **debayered basic file type with no colour baked in**. 4:2:0 is allowed with a
warning (user, 19 September). RAW never reaches the tool. QC-020 becomes a warning and QC-021 has
to be rebased on the real formats, which is pending Q1 below.

### A3. The encoding carrier is not `Input Color Space`, in 8 places

`docs/COLOR_AND_FORMAT.md:25`, `:127`, `:203`, `docs/WORKFLOW.md` (3),
`docs/COLOUR_SESSION_EXPORT.md` (1), `docs/MAC_SESSION.md` (1). Also
`proingest/core/scan.py:40`, which is code.

What is true: **`Gamma Notes` and `Color Space Notes`**, joined in that order, from the metadata
CSV. Verified 21 September to resolve to `S-Log3 S-Gamut3.Cine` on all five sample rows.
`Input Color Space` is a Resolve *clip property*, not a metadata field, which is why it is absent
from the CSV's 37 columns.

## 3. Open, and blocking the rewrite

1. **Which camera systems shoot RAW, and what is the "basic file type"?** The codec and container
   of the debayered export decide QC-020, QC-021 and what the decode has to handle. Each RAW
   system also debayers to its own native log and gamut, which needs a row in the input transform
   table (ARRI LogC3 and LogC4, RED Log3G10, BMDFilm Gen5, Canon Log3, Apple Log and the Sony
   variants are all in the pinned config already).
2. **Does the tool ever see the `.drt`, and where does it get the media?** From the shooters'
   consolidated folder, or from Ben? With no OTIO, the `.drt` is the only thing that states a
   timeline rate.
3. **The stringout: whose, and does the tool touch it?** The shooters make one. The docs say Ben
   exports one with the look and burn-ins. The shooters' spec lists a Turnover Stringout as a
   required deliverable with its own filename.
4. **Is the per-shot `.cube` still in the workflow?** Ben was described as exporting a CSV and an
   EDL. The docs carry a 65-point cube from Generate LUT as the exception for a shot the wheels
   could not do.
5. **Who supplies the per-shot extras?** HDRI, camera data, lens grid, BTS, reference stills. The
   tool cannot invent an HDRI. The sample folder had none of them.
6. **Is the project rate always 24?**
7. **`cl` or `cp` for a clean plate** (OQ-72), still open from 21 September.
