# Code and architecture review, 22 September 2026

Asked for by the user after the workflow alignment pass of the same day: a thorough review of
`proingest/` "with an eye on quashing any assumptions about alignment and workflow."

**The docs were corrected on 2026-09-21/22 and the code has not moved since 2026-09-16.** So this
is not a hunt for bugs against the spec the code was written to. It is an inventory of where the
code encodes a workflow that no longer happens, plus the things nobody has decided yet.

Everything under **Demonstrated** was run against `Turnover199_ForBEN/`, the real sample. Everything
under **Questions** is the user's call and is not built to a default.

---

## 1. The headline

**On the one real turnover we have, the tool today produces zero deliverables and three errors on
every row.** Three independent blockers, each of which alone auto-skips the row (PRD FR-6).

### Demonstrated

```
1. IDENTITY   naming.parse_clip_name("C0145.MP4")  -> None          => QC-010 error, every row
              naming.parse_clip_name("MELT0001_pl01") -> ShotIdentity(...)   (the old contract)

2. ENCODING   scan.SOURCE_ENCODING_KEY = 'Input Color Space'   <- the scan looks here
              The DATA IS PRESENT and resolves cleanly. Verified 2026-09-22:
                Gamma Notes + Color Space Notes = 'S-Log3 S-Gamut3.Cine'
                color.resolve_encoding(...)     -> 'S-Log3 S-Gamut3.Cine'   on all 5 rows
              The scan simply looks under a key that is not there.  => QC-046 + QC-047, every plate

3. RATE       C0145.MP4  stated_rate=24000/1001 -> QC-026 error
              C0148.MP4  stated_rate=24000/1001 -> QC-026 error
              C0152.MP4  stated_rate=24000/1001 -> QC-026 error     => QC-026 error, every row
```

Blockers 1 and 2 are known staleness: the respec is written and unbuilt. **Blocker 3 is not.** It is
a live defect in the spec that nobody has noticed, and it is question Q1 below.

## 2. Findings

### A0. The colour chain itself is correct and aligned. Verified.

Recorded first because the rest of this section is a list of defects and this is not one.

| | |
|---|---|
| Resolve project working space | **ACEScct** (user, 2026-09-22) |
| `color.WORKING_SPACE` | **`ACEScct`** |
| `color.PLATE_SPACE` | `ACEScg` |
| The input transform, per clip | `Gamma Notes` + `Color Space Notes` from the CSV |

Verified on the real sample: joining the two fields in order gives `S-Log3 S-Gamut3.Cine` on all
five rows, and `color.resolve_encoding` returns that canonical name for every one of them with no
new `INPUT_TRANSFORMS` entry. **So the Input Color Space data is in the CSV, the tool can resolve
it, and the space the tool grades in is the space the session grades in.** Ben sets each clip's
`Input Color Space` in his own session from those same two fields, so Resolve and the tool derive
the input transform from one string rather than two, and cannot disagree unless they resolve that
string differently - which is OQ-55 item (3) and the only thing here still wanting a test export.

The residual risk is narrower than "the encoding might be missing". It is a **misspelling**, which
is QC-047's job and is why that rule stays exact-match-or-refuse.

### A. There is no metadata CSV reader. At all.

The load-bearing half of the current workflow is entirely unbuilt, and it is worth stating as a
fact rather than a gap in a list:

```
grep -rn "import csv"           proingest/   -> nothing
grep -rn "utf-16"               proingest/   -> nothing
grep -rn "Shot Type"            proingest/   -> nothing
grep -rn "Gamma Notes"          proingest/   -> nothing
grep -rn "Color Space Notes"    proingest/   -> nothing
```

Identity and encoding both arrive in that file. Until it is read, no row can be named and no plate
can be colour-resolved. This is the first thing to build and everything else in section B depends
on its shape.

### B. The scan is built on the wrong input

| `core/scan.py:_choose_timeline` | QC-001 message is "no .otio or .edl found" | QC-001 is now "Ben's EDL or his metadata CSV is missing" |
| `core/scan.py:scan_turnover` | signature takes one `timeline_path` | Two required files, and `Turnover.timeline_path` is one field |

| `core/scan.py:_source_encoding` | clip metadata first, **container tag second** | The container carries nothing (measured). The second tier should be OQ-59's per-turnover default, not a tag |

### C. The identity model is structurally wrong, not just stale

This is the deepest change and the one most likely to be under-estimated.

`naming.ShotIdentity` is `(show, shot, elem_type, elem_index, aux, aux_index)`, where **`aux` is a
modifier hanging off an element**: `stem` is `MELT0001_pl01` and a colour chart is
`MELT0001_pl01_colorChart_01`. Three things follow from that shape and all three are now wrong:

- **A reference still is keyed to the shot code alone** (shooters' spec, 2026-09-21):
  `MELT0001_colorChart_01_4k_v01.exr`. Both `naming.aux_still_exr` and the `aux_still` row of
  `naming._output_patterns` carry the element segment, and QC-151 round-trips them, so they move
  together.
- **In the CSV, `colorChart` is a `Shot Type`** - a peer of `pl01`, not a modifier of one. The
  model wants to be `(shot_code, kind, index)` with `kind` drawn from plate types **and** still
  types, rather than an element with an optional aux.
- `planner.effective_identity` says "element, aux and index always come from the clip name, which
  the editor cannot change". Nothing comes from the clip name any more.

Dead with it: `naming.parse_clip_name`, `LENS_GRID_PATTERN`, `parse_lens_grid_name`,
`LensGridIdentity`, and `ui/shot_model.py`'s use of the first.

### F. OQ-60: the decode asserts nothing, and QC-018 cannot be built without a model change

`ffmpeg.decode_command` (`ffmpeg.py:280`) passes **no `-color_range`, no `in_color_matrix`, no
colorspace**. The only `bt709` in the file is at `ffmpeg.py:496`, which tags the **output** mp4.

`models.MediaInfo` has **no colour fields at all** - no `color_range`, `color_space`,
`color_transfer`, `color_primaries`. So QC-018 has nothing to compare and cannot be written until
`MediaInfo` grows them and `media.probe` fills them.

Measured on the sample: the default decode is bit-for-bit BT.601, **1.94% mean and 21.3% peak** in
ACEScg against BT.709. **This is the only finding in this review that ships wrong pixels under a
correct filename.** Everything else fails loudly.

### G. Sequencing: the EDL is read at the wrong time

`planner.plan_batch`'s docstring is explicit: *"The colour session is not a parameter here. It is
ingested onto the rows before a run (`clf.ingest`, PRD section 6 step 4)"*. That is the two-phase
flow: scan first, ingest Ben's EDL later.

**OQ-74 collapsed it.** The EDL arrives in the turnover folder with the media and is read at scan.
So `clf.ingest` is no longer a separate user-driven step in the normal case, and `scan_turnover`
has to do what it does. The Ingest button survives only for a **revised** EDL. That reshapes
`scan.py`, `clf.py` and `ui/color_session.py` together, and it is a sequencing change rather than a
find-and-replace.

### H. Smaller things, not recommendations

Per the house rule on surgical changes, these are named and not acted on.

- **`ShotRow.clip_name` is three join keys wearing one name**: the media match (CSV `File Name`),
  the EDL event match (`clf.MATCH_FIELD`, `FROM CLIP NAME`), and formerly identity. They are the
  same string today by construction. Naming them separately would make a future divergence visible.
- **`core/qc.py` is 1709 lines**, the largest module, and about ten rules are retiring from it.
- **Batch schema is `schema_version: 1`** and removing `SideFiles` and `clf_path` while adding the
  CSV path and `Shot Type` is breaking. See Q5.
- `ui/metadata.py`, `ui/shot_model.py` and `core/exports.py` all surface side files and camData in
  columns and sheets that will have nothing to show.

## 3. Questions

None of these is built to a default. Each changes what gets written.

### Q1. QC-026 fires on every clip of every real turnover. What should it do?

**The strongest finding in this review.** The delivered files state **24000/1001** and always will:
the shooters conform to 24.000 in Resolve, but a conform is a **timeline** property and Copy with
trim does not rewrite the file's rate. `media.probe` reads `r_frame_rate` into `stated_rate`,
`check_source_rate` compares it to the project's 24, and QC-026 is an **error**, which auto-skips
the row.

`media.py`'s own docstring anticipates the shape of this and solves only half: *"any rate baked into
the media may be stale camera metadata. Computing with that stale value would misread timecode and
block every row on QC-026."* Frame math correctly follows the timeline. The **rule** still fires.

Options: **(a)** downgrade to warning or info; **(b)** treat a 1000/1001 relationship to the project
rate as the normal conform and stay silent, so 23.976-against-24 passes while 25 or 30 still
reports; **(c)** retire it. **My read is (b)**: it keeps the rule meaningful for a file that genuinely
escaped the conform, which is what it was written for, and silent for the case that is now universal.

### Q2. Rows come from the CSV and events come from the EDL. What happens when they disagree?

Three cases, none specified:

- **A CSV row with no EDL event.** It has identity and encoding but no approved cut and no grade.
  QC-009 covers "the event carries no CDL"; there is no rule for "there is no event". Error on the
  row, presumably, but it needs an ID.
- **An EDL event with no CSV row.** Ben cut something the CSV does not describe. Turnover-scope
  info, or a warning?
- **Counts that match but names that do not.** Worth catching explicitly rather than as N separate
  row errors.

### Q3. Which frame of a reference still gets delivered?

The three stills in the sample are **one frame on the timeline inside a 49-frame file**. So the EDL
event names one frame out of 49 and QC-055 fires on all of them. Is the delivered frame the EDL
event's In, or the middle of the file, or the first? The EDL event's In is the only defensible
answer, but it makes the EDL load bearing for stills, which the "stills are never graded" rule
might have implied it was not.

### Q4. Handles are not symmetric. Does that matter to anything but QC-030?

Measured: `C0145` has 24 head and 24 tail; **`C0152` has 24 head and 8 tail**. "Expected handle
frames" is one Settings value driving one warning. Confirming that an asymmetric handle is normal
means QC-030 stays a warning and nothing else changes.

### Q5. Old batch files: migrate or refuse?

`schema_version: 1`, and this respec removes fields and adds others. `batchfile.py` has a migration
path. For a single-user pre-release tool, bumping to 2 and refusing 1 with a clear message is less
code than a migration nobody will run. But it is the user's call, and if any real batch exists it
is the wrong call.

### Q6. Does the per-turnover default input transform (OQ-59) replace the container-tag tier?

`scan._source_encoding` currently tries clip metadata, then the container's tags. The container
carries nothing on real media, so that second tier is dead weight. OQ-59's per-turnover default is
specified to sit exactly there. Confirming that it replaces the tag tier rather than sitting behind
it keeps the precedence to two levels instead of three.

## 4. Suggested order

Dependency order, not importance order. Each step is verifiable on `Turnover199_ForBEN/`.

1. **The CSV reader.** UTF-16, dynamic columns, duplicate `Shot Type` (QC-065), rows keyed by
   `File Name`, nothing read but identity and encoding. Verify: five rows, five `Shot Type` values.
2. **The identity model**, reshaped to `(shot_code, kind, index)`, both directions of `naming.py`,
   the reference-still rename, the collision-free casefold test. Verify: QC-151 round trip.
3. **The scan**, rebuilt on folder + EDL + CSV, OTIO dropped, QC-001 rescoped, QC-064 counting the
   ignored clips. Verify: the sample scans to five rows with no EDL present failing QC-001 first.
4. **Q1**, whatever it turns out to be, because until it is answered every row is skipped.
5. **The EDL read moved into the scan** (finding G), the Ingest button narrowed to a revised EDL.
6. **The removals**: side files, camData, BTS, lens grid, stringout, the cube, `_color`.
7. **OQ-60**: `MediaInfo` gains the colour fields, the decode asserts matrix and range, QC-018 built.
   Still wants one original camera file to confirm the direction.
