## 1. The headline

**The pipeline runs nearly end to end on real media, and the real EDL breaks the match.**

- With QC-026 patched out in a scratch script only, `Turnover199` plus a synthetic EDL scanned to
  five correct rows and planned twelve deliverables. **Eight landed to spec**: EXRs in DWAA 45,
  ACEScg, `timeCode` in the header, frames from 1001, stills converted and never graded, the wav,
  both spreadsheets. **All four reference mp4s failed QC-113**, because they play at 24000/1001.
- **Ben's real EDL arrived on 2026-09-23** (`Turnover199/Turnover199.edl`). It carries **no
  `FROM CLIP NAME` line on any event and every reel is `AX`**. `clf.MATCH_FIELD` and the reel
  fallback both miss, so **every row of the real turnover is QC-066 today**. Measured.
- **Source timecode matches all five events unambiguously**: each event's source range sits inside
  exactly one file's timecode range, 24 frames in, with the durations the `.drt` records
  (`C0145`: file from 830946, event 830970 to 831201, 232 frames). The parser reads the events and
  the CDLs correctly, CRLF included. Only the matching is wrong.

Architecture is sound: no Qt in core, no import cycles, subprocesses only through `ffmpeg.py`. The
CDL math, ACEScct constants, EXR headers and integer frame trimming were each checked and are right.

## 2. Decisions, 2026-09-22 and 2026-09-23 (user)

| # | question | decision |
|---|---|---|
| D1 | Frame rate | **Every source is rendered at 24, frame for frame.** 24000/1001 is the normal conform and is silent. **Any other rate, 25 or 30, is a must-fix**: the batch does not run until it is fixed |
| D2 | Plate audio | **Trimmed to the EDL event, exactly like the picture, and follows the video duration**: retimed by 1000/1001 so it stays locked to the 24 fps picture |
| D3 | A clip used twice on the timeline | Each instance has its **own CSV row and its own shot code**, and each shot code is a deliverable. Matching is by source timecode, so both are handled |
| D4 | Reference stills | **Never ignore the EDL.** A still delivers its event's frame. A still with no event is a must-fix |
| D5 | Unrecognised `Shot Type` | **Must-fix warning** in the UI, and the row gets no deliverables. `BTS` and `lensgrid` are ignored only when they carry no `Shot Type` |
| D6 | The same shot code + type + index twice | **Must-fix warning**. Neither row runs until it is corrected |
| D7 | Other `.edl` or `.csv` in the folder | **Exactly one of each**, as built |
| D8 | How warnings are fixed | The user **drops corrections into the folder and re-scans**. Every must-fix is fixed before the batch runs |
| D9 | QC tiers | **Two tiers: must-fix (blocks the run) and info (shown, never blocks).** The list in section 4 is the proposal |
| D10 | Plate range | **The cut only.** The EDL event's source In/Out, no handles. Audio follows |
| D11 | Failed outputs | **No `.failed` sidecar.** The row is marked failed and names exactly which output failed and why. The user fixes the cause, **resets the row** and it re-runs |
| D12 | Completed shots | Skipped on the next Run. **Right-click Re-run** on a row forces it |
| D13 | Shot tracker | **Exactly one line per shot code**, as `docs/Pre Pro Shot Tracker - W1.csv` shows. One line per CSV row is a defect |
| D14 | Editor notes | The tracker has no Notes column; notes stay in the app and the QC log. `UI_SPEC.md` is corrected |
| D15 | Locks | The list and the delivery root are **read-only during a scan and during a run** |
| D16 | A moved turnover | The batch remembers where each turnover was. A missing folder **warns on its turnover heading**; right-click **New folder location** and it reloads, keeping trims, skips, notes and delivered state matched by `File Name`, and warning if the EDL or CSV changed |
| D17 | Colour matrix | **BT.709** on decode and on the reference encode, provisional. If it proves wrong it is switched in the next version (OQ-60) |
| D18 | Old `.pibatch` files | None exist. Version 1 stays refused |

## 4. The two QC tiers, proposed (D9)

**Spelled out 2026-09-23 at the user's request**, with QC-026 moved to must-fix for 25 or 30 fps. Must-fix blocks the run until the folder is corrected
and re-scanned. Info is shown and never blocks. Phase B (QC-1xx) is not tiered: any failure marks
the row failed and names the output (D11).

### Must-fix: the run does not start until the folder is corrected and re-scanned

| rule | what it catches |
|---|---|
| QC-001 | The folder has no EDL or no metadata CSV, or has two of either |
| QC-002 | The EDL or the CSV will not parse |
| QC-004 | The CSV has no rows, or the EDL has no events |
| QC-008 | No event in the EDL carries a CDL: the session was exported without the grade |
| QC-009 | This row's event carries no CDL, so the row would render ungraded |
| QC-010 | A row with a `Shot Type` but a blank or malformed `Shot` |
| QC-010 (D5) | **A `Shot Type` the tool does not recognise**, such as a typo. The row gets no deliverables |
| QC-011 (D6) | **Two rows with the same shot code, type and index**, which would write the same files. Rekeyed from the filename to the identity |
| QC-012 | The CSV names a `File Name` that is not in the folder |
| QC-013 | A `File Name` matches more than one file |
| QC-014 | ffprobe cannot read the file |
| QC-022 | ffmpeg cannot decode the codec |
| QC-023 | The source is not 3840x2160. With "allow non-4k" on it drops to info and is letterboxed |
| **QC-026** | **The file's frame rate is not 24 or 24000/1001, such as 25 or 30** (user, 2026-09-23). 24000/1001 is the normal conform and is silent |
| QC-027 | Drop-frame timecode |
| QC-029 | The event asks for frames the file does not have |
| QC-031 | After an edit, In or Out is outside the media |
| QC-032 | After an edit, In is after Out |
| QC-042 | A plate's audio is present but unreadable |
| QC-046 | The CSV names no encoding (`Gamma Notes` and `Color Space Notes` empty) |
| QC-047 | The encoding named cannot be resolved to exactly one input transform |
| QC-062 | The delivery root cannot be written to |
| QC-063 | Not enough free space at the delivery root for the estimated output |
| QC-065 | The CSV's two `Shot Type` columns both name a type, and they disagree |
| QC-066 | No event in the EDL falls inside this row's file: no approved cut, no grade. Applies to stills too (D4) |
| new | **One event falls inside two files' timecode, or two events fall inside one row's file**: the match is ambiguous and the tool will not choose |

### Info: shown in the list and the QC log, never blocks

| rule | what it says |
|---|---|
| QC-005 | The folder name does not follow `turnover###_MM_DD_YYYY_name` |
| QC-015 | An image sequence has a gap in its frame numbers |
| QC-018 | The file's own colour tags contradict the encoding the CSV names (built in chunk G) |
| QC-020 | The source is 8-bit or 4:2:0 |
| QC-021 | Codec, bit depth and chroma of the source, for the record |
| QC-028 | The source has no timecode, so the EXRs carry none |
| QC-030 | Fewer handle frames than "expected handle frames" beyond the cut |
| QC-033 | The cut is shorter than the minimum duration setting |
| QC-034 | The cut is longer than the maximum duration setting |
| QC-035 | In/Out differ from what was scanned |
| QC-036 | The shot code was edited in the app |
| QC-040 | A plate has no audio (fixed: embedded audio counts) |
| QC-041 | More than one audio source for one plate |
| QC-043 | The audio length differs from the plate by more than a frame |
| QC-044 | The audio is not 16-bit PCM and is converted |
| QC-045 | The editor trimmed In/Out away from the approved cut |
| QC-048 | Which colour chain the row renders through |
| QC-055 | A still's event covers more than one frame; the event's In is used |
| QC-060 | Deliverables exist at version N; this run writes N+1 |
| QC-061 | A complete set exists; the row is skipped (D12) |
| QC-064 | N clips in the folder carry no `Shot Type` and were ignored |
| new | An EDL event has no CSV row |
